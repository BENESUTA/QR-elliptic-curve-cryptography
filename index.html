やり取りの記録

まず①で鍵を作りましょう。

鍵をどうやって渡す？

暗号は「鍵」で内容を隠します。ところが相手に鍵を渡す道で盗まれたら意味がありません。これを鍵配送問題といいます。

解決のヒントはペンキの混色です。二人が共通の黄色を持ち、それぞれ秘密の色（Aは青、Bは赤）を混ぜて交換します。受け取った色に自分の秘密色を足すと、二人とも「黄＋青＋赤」の同じ色になります。盗聴者は混ざった色から元の色を取り出せません。楕円曲線暗号（ECDH）は、この「混ぜる」を点の足し算で行います。

楕円曲線と点の足し算

楕円曲線は y² = x³ + ax + b のグラフで、とがりや自己交差がない（4a³ + 27b² ≠ 0）ものを使います。下の図では a, b や P, Q の位置を動かせます。曲線上の2点 P, Q の「和」は次の作図で決めます。

① P と Q を通る直線を引き、曲線との3つ目の交点 R を求める。② R をx軸で上下に反転した点が P+Q。P=Q のときは接線を使います。

作図を式にすると、傾き λ を使って次のようになります。

P≠Q のとき  λ = (y₂ − y₁) / (x₂ − x₁)
P=Q  のとき  λ = (3x₁² + a) / (2y₁)
x₃ = λ² − x₁ − x₂
y₃ = λ(x₁ − x₃) − y₁      ← P+Q = (x₃, y₃)

「余り」の世界（有限体）に移す

実数のままだと小数が延々と続き、コンピュータでは扱いにくく、誤差も出ます。そこで、すべての計算を素数 p で割った余りで行います（時計の計算と同じ）。すると座標はとびとびの整数になり、曲線は点の散らばりになります。

難所は割り算です。mod p の世界では「÷2」は「2の逆数を掛ける」ことで、逆数は「掛けて1余りになる数」です。p=17 なら 2×9=18≡1 なので、÷2 は ×9 です。

例：曲線 y² = x³ + 2x + 2 (mod 17)、G=(5,1) を2倍します。

λ = (3·5² + 2) / (2·1) = 77/2 ≡ 9 · 9 = 81 ≡ 13  (mod 17)
x₃ = 13² − 2·5 = 159 ≡ 6
y₃ = 13·(5 − 6) − 1 = −14 ≡ 3
→ 2G = (6, 3)

G を k 回足す（スカラー倍）

G を k 回足した点を kG と書きます。下の図で k を動かすと、点が不思議な順で飛び回ります。素数 p、a、b、始点 G も変えられます（初期設定は p=17, a=2, b=2, G=(5,1)）。

足し続けると、いつか「無限遠点 O」（足し算での 0）に戻って一周します。その回数を G の位数といい（初期設定では19）、位数 n なら nG = O で、(n−1)G は G の上下を反転した −G になります。O は座標をもたないので図には点が出ません。点の並びに規則性は見えず、kG から k を逆算するのは困難です。

実際の暗号では k が2²⁵⁶ほどもあります。ただし順番に足す必要はなく、倍々にして必要な分だけ足せば速く計算できます（ダブル＆アド）。例：13 = 8+4+1 なので 13G = 8G + 4G + G。256ビットでも約256回の倍加と加算で済みます。

逆に、G と kG から k を求める問題を楕円曲線の離散対数問題といい、今の計算機では現実的な時間で解けません。ここが安全性の根拠です。

鍵交換（ECDH）のしくみ

A：秘密 a → 公開 A = aG        B：秘密 b → 公開 B = bG
A と B を交換（QRで渡す）
A は a·B = a(bG)、B は b·A = b(aG) を計算
どちらも (ab)G で同じ点！

ペンキの例えで言えば、黄色が G、混ぜる回数が秘密鍵です。盗聴者は G, aG, bG を知っても abG を作れません。

なぜ「楕円」曲線？ 足し算の順番を変えても大丈夫な理由

曲線の形は楕円ではありません。名前は、楕円の周の長さを求める計算（楕円積分）から生まれた歴史に由来します。

この「点の足し算」は、数の足し算とよく似た4つの性質をもちます（数学では群といいます）。

① 0にあたる点：無限遠点 O      P + O = P
② 逆向きの点：−P = (x, −y)     P + (−P) = O（縦線は無限遠で交わる）
③ 交換法則：P + Q = Q + P       （2点を通る直線は順番に関係ない）
④ 結合法則：(P+Q)+R = P+(Q+R)  （証明は大学レベルだが成り立つ）

特に④のおかげで、G を何回足すかだけで答えが決まり、足す順番は関係ありません。だから次の式が成り立ち、アリスとボブは同じ点にたどり着きます。

a(bG) = G を b 回足したものを a 回足す = G を ab 回足す = b(aG)

p=17 の例なら −G = (5, −1) = (5, 16) で、18G と一致します。

割り算（逆数）の求め方と、p が素数でなければならない理由

mod p の世界の割り算は「逆数を掛ける」ことでした。逆数の求め方は2通りあります。例として 6 の逆数（mod 17）を求めます。

【フェルマーの小定理】 a^(p−1) ≡ 1 なので a の逆数は a^(p−2)
6² = 36 ≡ 2,  6⁴ ≡ 4,  6⁸ ≡ 16
6¹⁵ = 6⁸·6⁴·6²·6 ≡ 16·4·2·6 = 768 ≡ 3   → 6⁻¹ = 3
（このサイトのプログラムはこの方法です）

【ユークリッドの互除法】
17 = 2·6 + 5,  6 = 1·5 + 1
1 = 6 − 5 = 6 − (17 − 2·6) = 3·6 − 17
→ 3·6 ≡ 1 (mod 17)   → 6⁻¹ = 3

p が素数でないと、逆数のない数が出てきます。たとえば mod 15 では、3 に何を掛けても 0, 3, 6, 9, 12 のどれかで、1 になりません。素数なら 0 以外のすべての数に逆数があり、足し算だけでなく割り算も自由にできる世界（有限体）になります。

曲線上の点は何個ある？ 位数と安全な曲線

曲線上の点の数（O も含む）を N とすると、p が大きいとき N は p+1 に近く、差は 2√p 以内に収まります（ハッセの定理）。p=17 なら 18 ± 8.2 の範囲で、実際は19個でした。

G の位数 n（nG = O となる最小の n）は、必ず N の約数になります。N が素数なら、O 以外のどの点を G にしても位数は N です。p=17 の曲線の N=19 が素数なので、図ではどの点も一周に19回かかりました。

N が合成数だと、小さな位数の点が混ざり、そこだけ探索が楽になります。実際の曲線は、N がほぼ素数で位数がとても大きくなるように選ばれています（secp256k1 の位数は約 2²⁵⁶）。上の図で a, b を変え、始点 G の位数を見比べてみてください。

公開鍵が33バイトに収まる理由（点の圧縮）

点 (x, y) は座標が2つですが、x が決まれば y は2通りしかありません（y と p−y）。p は奇数なので、この2つは片方が偶数でもう片方が奇数です。そこで x と「y が偶数か奇数か」の1ビットだけ送れば点が復元できます。

公開鍵 = 02 または 03（偶奇） + x（32バイト）= 33バイト

復元では、まず z = x³ + 7 を計算します。z が平方数（ある数の2乗）でなければ、その x に点はなく、不正な鍵として捨てます。p ≡ 3 (mod 4) の素数なら、平方根は y = z^((p+1)/4) で求まります。secp256k1 の p はこの形です。このサイトのプログラムもこの式で復元し、y² = z になるかを確かめています。

ダブル＆アドと、解読にかかる手間の差

13G を、13 = 8 + 4 + 1（2進数で 1101）と分けて作ります。

G → 2G → 4G → 8G     （倍加 3回）
8G + 4G = 12G,  12G + G = 13G （加算 2回）
合計5回（順に足すと12回かかる）

256ビットの秘密鍵でも、倍加256回と加算が平均128回ほどで済み、スマホでも一瞬です。

一方、G と kG から k を探すのは、総当たりなら約 2²⁵⁶ 回です。もっと賢い方法（ρ法など）でも約 √(2²⁵⁶) = 2¹²⁸ ≈ 3×10³⁸ 回かかります。作るのは約384回、探すのは10³⁸回。この差が安全性の源です。同じ強さの RSA 暗号は 3072ビット前後の鍵が必要とされ、楕円曲線の256ビットは短くて速いのが利点です。

実際に使うときの注意点（安全のために） 
■ 鍵はそのまま使わない
  共有点の x を SHA-256 や HKDF で混ぜてから暗号の鍵にする。
■ 使い捨ての鍵（前方秘匿性）
  通信ごとに鍵ペアを作れば、後で秘密鍵が漏れても過去の通信は読まれない。
■ 暗号化は認証つきで
  AES-GCM は改ざんも検知する。iv（初期値）は毎回ちがうものにし、
  同じ鍵での使い回しは厳禁。
■ 相手が本物か確かめる
  鍵交換だけでは、間にいる攻撃者が両者と別々に鍵交換する
  「中間者攻撃」を防げない。確認コードの照合や電子署名（ECDSA）、
  証明書で相手を確認する。
■ 受け取った点の検証
  曲線上にない点を送り込む攻撃があるので、必ず y² = x³+ax+b を確認する。
■ 実装は自作しない
  計算時間や消費電力から秘密鍵が漏れる攻撃（サイドチャネル）がある。
  本番では WebCrypto や libsodium など検証済みのものを使う。
どこで使われている？ これからはどうなる？

よく使われる曲線は次のとおりです。

secp256k1  ビットコインなど（このサイトも使用）
P-256      Webの通信（TLS）、パスキーなど
Curve25519 Signal、WireGuard など

ただし、十分に大きな量子コンピュータが実現すると、ショアのアルゴリズムで離散対数問題も解けてしまいます。そのため、量子コンピュータでも解けないとされるポスト量子暗号（たとえば標準化された ML-KEM）への移行が進んでいます。現在は、従来の楕円曲線暗号と組み合わせて使う方式も増えています。

このサイトの中身

曲線は secp256k1（y² = x³ + 7、p = 2²⁵⁶ − 2³² − 977）です。乱数の秘密鍵 d から Q = dG を作り、33バイトに圧縮してQRにします。共有点 S の x座標を SHA-256 で混ぜて AES-256-GCM の鍵にし、メッセージを暗号化・改ざん検知します。QRの文字列は大文字の英数字だけにして、小さなQRで済むようにしています。

注意：学習用の実装です（計算時間が一定でないなど）。実際のサービスでは検証済みのライブラリを使い、確認コードの照合で相手の本人確認をします。
