鍵をどうやって渡す？

暗号は「鍵」で内容を隠します。ところが相手に鍵を渡す道で盗まれたら意味がありません。これを鍵配送問題といいます。

解決のヒントはペンキの混色です。二人が共通の黄色を持ち、それぞれ秘密の色（Aは青、Bは赤）を混ぜて交換します。受け取った色に自分の秘密色を足すと、二人とも「黄＋青＋赤」の同じ色になります。盗聴者は混ざった色から元の色を取り出せません。楕円曲線暗号（ECDH）は、この「混ぜる」を点の足し算で行います。

楕円曲線と点の足し算

楕円曲線は y² = x³ + ax + b のグラフで、とがりや自己交差がない（4a³ + 27b² ≠ 0）ものを使います。下の図では a, b や P, Q の位置を動かせます。曲線上の2点 P, Q の「和」は次の作図で決めます。

① P と Q を通る直線を引き、曲線との3つ目の交点 R を求める。② R をx軸で上下に反転した点が P+Q。P=Q のときは接線を使います。

作図を式にすると、傾き λ を使って次のようになります。

P≠Q のとき  λ = (y₂ − y₁) / (x₂ − x₁)
P=Q  のとき  λ = (3x₁² + a) / (2y₁)
x₃ = λ² − x₁ − x₂
y₃ = λ(x₁ − x₃) − y₁      ← P+Q = (x₃, y₃)

「余り」の世界（有限体）に移す

実数のままだと小数が延々と続き、コンピュータでは扱いにくく、誤差も出ます。そこで、すべての計算を素数 p で割った余りで行います（時計の計算と同じ）。すると座標はとびとびの整数になり、曲線は点の散らばりになります。

難所は割り算です。mod p の世界では「÷2」は「2の逆数を掛ける」ことで、逆数は「掛けて1余りになる数」です。p=17 なら 2×9=18≡1 なので、÷2 は ×9 です。

例：曲線 y² = x³ + 2x + 2 (mod 17)、G=(5,1) を2倍します。

λ = (3·5² + 2) / (2·1) = 77/2 ≡ 9 · 9 = 81 ≡ 13  (mod 17)
x₃ = 13² − 2·5 = 159 ≡ 6
y₃ = 13·(5 − 6) − 1 = −14 ≡ 3
→ 2G = (6, 3)

G を k 回足す（スカラー倍）

G を k 回足した点を kG と書きます。下の図で k を動かすと、点が不思議な順で飛び回ります。素数 p、a、b、始点 G も変えられます（初期設定は p=17, a=2, b=2, G=(5,1)）。

足し続けると、いつか「無限遠点 O」（足し算での 0）に戻って一周します。その回数を G の位数といい（初期設定では19）、位数 n なら nG = O で、(n−1)G は G の上下を反転した −G になります。O は座標をもたないので図には点が出ません。点の並びに規則性は見えず、kG から k を逆算するのは困難です。

実際の暗号では k が2²⁵⁶ほどもあります。ただし順番に足す必要はなく、倍々にして必要な分だけ足せば速く計算できます（ダブル＆アド）。例：13 = 8+4+1 なので 13G = 8G + 4G + G。256ビットでも約256回の倍加と加算で済みます。

逆に、G と kG から k を求める問題を楕円曲線の離散対数問題といい、今の計算機では現実的な時間で解けません。ここが安全性の根拠です。

鍵交換（ECDH）のしくみ

A：秘密 a → 公開 A = aG        B：秘密 b → 公開 B = bG
A と B を交換（QRで渡す）
A は a·B = a(bG)、B は b·A = b(aG) を計算
どちらも (ab)G で同じ点！

ペンキの例えで言えば、黄色が G、混ぜる回数が秘密鍵です。盗聴者は G, aG, bG を知っても abG を作れません。

このサイトの中身

曲線は secp256k1（y² = x³ + 7、p = 2²⁵⁶ − 2³² − 977）です。乱数の秘密鍵 d から Q = dG を作り、33バイトに圧縮してQRにします。共有点 S の x座標を SHA-256 で混ぜて AES-256-GCM の鍵にし、メッセージを暗号化・改ざん検知します。QRの文字列は大文字の英数字だけにして、小さなQRで済むようにしています。

注意：学習用の実装です（計算時間が一定でないなど）。実際のサービスでは検証済みのライブラリを使い、確認コードの照合で相手の本人確認をします。
